# 完整历史备份与模型接续

生效：2026-11-05（北京时间）。用户明确要求：放宽存储预算，约 10 GiB 也可接受；未来备份 ZIP 应保存迭代历史，让其他模型能够理解变化过程。容量只在 AGENTS 第 15 项定义，本页规定导出格式；其他已认可规则继续有效。

## 什么时候使用

用户要求导出本资料库备份、完整 ZIP 或迁移交接时，默认采用本约定。普通“将指定成果存入 GitHub”仍是相关文件的普通提交，不每次另造全库 ZIP。GitHub 网页自带 Download ZIP 仅是文件快照，其行为不能由本规则改变。

## 一个备份包应该有什么

| 项目 | 内容与用途 |
| --- | --- |
| `files/` | 备份时指定主分支／提交的已跟踪文件，便于直接阅读和使用 |
| `repository.bundle` 或等效完整镜像 | 从有权限读取的远端取得全部分支、标签及其可达的完整提交、树和文件对象；不用浅克隆，不压扁或重写历史 |
| `HISTORY.md` | 可读迭代索引：时间、提交编号、修改内容、已记录的原因、关键选择／否定与对应证据；主线概述并指向详细 Git 历史 |
| `HANDOFF.md` | 新模型先读的入口：库用途、当前有效规则与决定、项目位置、产物、缺口、待办和下一步；明确旧规则已被哪版取代 |
| `MANIFEST.json` | 仓库地址、备份时间、默认分支、目标 HEAD、所有分支／标签及哈希、提交计数口径、文件清单／校验值、实际保存范围与缺口 |
| `RESTORE.md` | 从本包恢复、检查历史与继续工作的具体步骤；写明实际执行过哪些恢复验证 |
| 需要单独处理的内容 | 实际使用的 Git LFS 对象、子模块／嵌套仓库历史，以及明确要求保存的库外原件或平台记录，逐项列状态 |

Git 历史保留已经提交的变化；可读索引让新模型不用先读遍所有差异。不编造历史原因、用户认可或未保存的聊天；理由未记录时标未知。摘要用于导航，不能替代 bundle 和原件。

## 如何制作与核验

1. 先核对远端、权限、当前分支和未提交修改；从可信远端取得完整镜像或等效完整历史，不使用 `--depth`。清单记录当前可读取的引用与范围；已彻底删除且不可取得的历史不能声称包含。
2. 可在仓库外的独立备份目录执行 `git clone --mirror <仓库地址> repository.git`，再用 `git -C repository.git bundle create ../repository.bundle --all` 生成离线历史包。凭据走正规认证，不写入命令示例、清单或归档；不用普通下载 ZIP 替代此步骤。
3. 生成当前文件快照、可读迭代索引、接续说明和清单。明确要求保存的未提交成果另存并标注，不能冒充已经进入 Git 历史。外部原件只留位置时注明原件未备份。
4. 在临时目录从 bundle 恢复镜像，执行 `git bundle verify`、恢复仓库的 `git fsck --full`，比对源与恢复后的分支／标签、目标 HEAD、提交计数及当前文件校验值。核验浅克隆状态，检查可读接续说明确实指向有效文件；只有实际通过才报告通过。
5. 使用 LFS 时另取得所需实际对象并验证；bundle 不自带这些大文件。子模块的独立历史另备份。Issue／PR 讨论、Wiki、账号聊天和库外附件不属于普通 Git 文件历史，需要时另行导出并列清单，不能默认宣称已包含。
6. 在仓库外制作 ZIP，解压该 ZIP 后再做关键恢复核验并记录结果，给出包路径、大小、对应 HEAD、校验值及缺口。缺历史或未通过恢复检查时标“未完成完整历史备份”，不把备份按钮点击成功当作完成。

完整包不提交回被备份的同一个 Git 仓库，避免递归打包和历史膨胀；保存在用户指定的本地／独立备份位置。预算按实际需要调整，不以旧阈值截断历史、丢掉原件或自动删除已有备份。保密要求仍适用，不能把含历史的私有包发布到公开位置。

## 后续修改怎样帮助新模型理解

重要修改的提交说明写清“改了什么、为什么、适用范围”；关键反馈与取舍留相关项目记录，通用规则只维护当前有效正文。HISTORY 保留迭代路径，HANDOFF 先指出当前决定，避免把历史上被否定的方案误当现行要求。临时连接故障只记录必要状态，不复制整段工具日志。
