## 与现有管理层合并

沿用 [AGENTS](../AGENTS.md) 的真实能力、来源证据、分类归档与原件保护；沿用 [COLLABORATION](COLLABORATION.md) 的自主推进、有限重试、范围验收和新工具实测要求。只补充材料处理路径，不把某个工具设为全局必用项。

1. **按材料取证**：网页先读正文；图文直接看原图，必要时 OCR 并核对；视频先查可用字幕，无合适字幕再考虑音频转写；画面承载信息时回看原片或关键帧。
2. **分开三层**：作者原始材料、AI 摘要与推断、我们采纳的决定分别标识。关键结论附 URL、作者、读取日期与时间点／页码／图号；覆盖不足写明缺口。
3. **先任务后采集**：围绕当前问题选择材料，先做一个样本，比较旧方法与新流程的完整性、错误、人工时间和成本，再决定是否批量化。
4. **重复工作交给工具**：在具备执行环境且任务需要时，用脚本做下载、去重、文件检查与格式整理；模型承担理解、比较与创作判断。不能因未装工具停止可行的直接阅读。
5. **分层归档**：GitHub 保存可追溯笔记、决定与必要文本；视频、图片和可编辑源保留主副本及位置，按实际备份范围处理。仅有链接注明原件未备份。约 10 GiB 是可调规划参考，不是停止线；不删唯一原件来缩小仓库。

## 对我们的具体用途

| 工作 | 怎样使用 | 必须补的判断 |
| --- | --- | --- |
| 用户分享的抖音／X 图文 | 原文和原图 → 核对一手项目 → 提炼用途 → 记录采用与不采用项 | 不凭标题认定模型能力；不把概念宣传直接变成总规则 |
| 长发布会、教程、访谈 | 字幕或转写 → 分段定位 → 回查关键说法 → 按问题总结 | 名字、数字、限制条件要回查；文本不足以证明操作成功 |
| 创意设计与动画鉴赏 | 画面／关键帧与必要声音并读，研究构图、色彩、动作、节奏，再关联当前作品 | 不能把“读完字幕”称为看完作品，更不能据此评价全部视听效果 |
| GitHub 资料库与换模型接续 | 保存来源、采用理由、实际产物、验证和下一步；沿用完整 Git 历史备份约定 | 新模型按需读取；归档不等于永久记忆或模型训练 |

### 合并后的读取与验收方法

1. 先辨别视频还是图文。图文逐图读取；视频记录来源、ID、总时长及取得方式。
2. 获取可用字幕或完整音频，检查真实媒体时长；保留原始字幕并标自动生成来源。无字幕时进行全音频转写，输出带时间戳文本；不得把 Whisper 示例中 pad_or_trim 的 30 秒当整片。
3. 对画面承载的图表、代码、操作结果另作关键帧／OCR／视觉核对。抽样注明范围；研究剪辑、动作和节奏需要连续片段，不能只读字幕。
4. 将原文、识别结果、解释和采纳决定分开；检查转写缺口、静音幻觉、重复、专名与数字，重要说法回查时间点。
5. 归档最小可追溯包：来源信息、带时间戳转写、必要证据图、总结、采纳决定、缺口及处理版本。媒体主副本与缓存分开；沿用约 10 GiB 弹性规划，不全量搬运 funNLP 语料或默认生成长图／切片。
6. 验收必须分别报告取得、转写、视觉核对、归档是否完成。vnotes 的 self-test 使用合成数据验证排版链路，不能替代真实视频验收。上述流程为已采纳方法；未实现的视觉复核与自动归档仍需单独部署和实测。
