# 下一次设计与修改工作卡

由《羊年》与《汉字重构》的真实反馈提炼。按任务调用；不把本题的红金、卷角或书法风格强套到其他项目。

## 先判断这次到底要做什么

| 当前请求 | 应进入的工作 | 本项目发生过的误判 |
|---|---|---|
| “重新设计、这个方向不喜欢” | 重新比较结构机制和总形 | 在被否定稿上换颜色、修几条线 |
| “羊不像、太怪、太凶” | 比较头颈、重心、姿态与关键特征 | 只加角、只圆嘴、反复补五官 |
| “字图没有关联、看不出创意” | 检查共享关系、动作、围合及空间组织 | 把碰到一个端点说成完整共构 |
| “图案可以，只改排版” | 冻结造型，调整位置、字号、阅读路径 | 重新生成导致羊形和字形走样 |
| “严格按照这两只小羊” | 复用指定组件，只做授权的缩放与平移 | 再解释成一只新的动物 |
| “横版、竖版都要” | 分清画布方向、整体构图和文字方向 | 只换画布，或压扁原字形 |

## 开放设计：让资料真正影响选择

1. **把问题落到画面。**例如“像鹿”要检查是否头颈过长、类别线索弱；“太散”要找出哪些空隙把一句话拆成独立组。
2. **按问题调资料。**需要整体体态，回到姿态和总形案例；需要识别，比较类别特征和误读；需要节目感，回到完整主标与场景。只补当前判断缺少的证据。
3. **用少量不同机制比较。**如字骨参与动物、负空间形成形体、总轮廓与笔势组织。每稿指出实际变化，不以三种配色充当三种创意。
4. **在简化画面上看核心关系。**去掉说明、背景和质感后，再看文字、意象、重心与主题关系；单色是诊断工具，不强制成为最终风格。
5. **主动筛掉弱稿。**需要听解释才能看出羊、两句标题断读、文字和动物同时受损，均应回到相应问题层，不以“后续精修”掩盖。
6. **在完整布局中再判断。**局部羊首漂亮，不等于装进主标后尺度、朝向、阅读与气质合适。先看整体，再放大关键连接。

## 收到反馈后，先判层级再修改

| 问题层 | 判断信号 | 合适动作 |
|---|---|---|
| 命题 | 用途、文案或气质理解错了 | 更新命题，撤回沿错误目标形成的限制 |
| 概念 | 普通、没有独立创意、图文堆叠 | 更换核心关系或结构载体 |
| 结构 | 像鹿、像蛇、拱背、空间失衡 | 调整类别线索、比例、连接和姿态 |
| 排版 | 太散、读成另一句话、字被压扁 | 调阅读路径、近邻分组、字号和位置 |
| 执行 | 改错底稿、轮廓走样、字体不正 | 取回正确资产，使用可控排字或组件组装 |

本项目中“更抽象”和“更像羊”经常一起出现，不能只选其中一句执行。应减少不承担作用的细节，同时保留足以形成羊的关系。

## 已选稿修改：让进展能够积累

1. 保存明确的修改前基准，记录认可范围。例如“这两只小羊的轮廓”，不能扩大为“整套设计已经定稿”。
2. 将造型、书法主字、正规辅字、印章、背景分成可复用组件；严格复制优先采用同一来源的组件。
3. 仅改本轮指定变量。若它确实牵连相邻部分，写明必要联动及范围，避免暗中扩大任务。
4. 与基准并排核对：指定问题改善了吗；已认可关系保住了吗；有没有新增错字、改字形、改变主羊或阅读顺序。
5. 横竖版复用同一母组件。允许位置和等比大小变化，避免为了凑幅面拉伸字形或分别重绘。
6. 如实登记结果：局部编辑近似延续、轮廓完全复用、原生文字层、路径重绘，是不同交付性质。

长提示词能约束意图，不能证明像素和轮廓已被锁住。固定造型连续走样时，应改变制作方式；继续增加“不要改”不足以解决。

## 本次积累的设计雷点

| 雷点 | 早期信号 | 立即修正 |
|---|---|---|
| 用说明补创意 | 解释越来越长，实际共享位置说不清 | 指出画面证据，承认未实现的关系 |
| 用资料量证明能力 | 交付重点是看了多少案例 | 给出它让本轮改变的具体选择 |
| 将用户提示算作独立创意 | 只延伸用户已说的江流、人物、生肖 | 标明来源，另提有依据的结构发现 |
| 机械删笔 | 羊变成卷钩、问号、云纹 | 恢复关键关系，重新比较姿态 |
| 为文字拉长动物 | 羊成了装字容器，颈身比例异常 | 同时重排文字与动物空间 |
| 高度同构压过用途 | 动物和字都勉强，仍称核心创新 | 降低融合强度或更换结构载体 |
| 每字都抢表现 | 四个大字、羊和印章同时强变形 | 明确主要发现和稳定阅读锚点 |
| 同色同质糊成一块 | 图和字靠说明才能分开 | 比较线面、间隙、笔重与色差 |
| 只靠换色救结构 | 加金属、飞白后类别仍不明 | 回到比例、连接、姿态和空白 |
| 画布横了就算横版 | 字组仍散、读法未调整 | 分别检查画布、构图、文字方向 |
| 紧凑等于压扁 | 国框、主竖或书法重心变形 | 恢复宽高比，以位置与尺度重排 |
| 传统出处压过现代阅读 | 有文物根据，成图仍怪 | 转译结构规则，重新看当前效果 |
| 错把局部反馈永久化 | “永不拆字”“主羊永远向内” | 结合当时底稿和最新选择理解 |
| 只改小字却重画整图 | 指定问题稍好，羊形和字形变了 | 回到正确底稿做可控局部处理 |
| 自查被写成验收 | 文件正确就称正式定稿 | 分开记录技术检查、视觉判断、用户认可和场景验证 |

## 每次留下这一条记录

```text
问题：用户指出或我主动发现了什么？
依据：哪条反馈、参考或成图事实支持判断？
改动：实际改了哪一条线、哪块留白、哪个位置或字形？
结果：原尺寸与整体布局中出现了什么变化？
决定：保留 / 回退 / 淘汰 / 待确认。
适用范围：这条经验在哪种任务成立，什么情况下不能套用？
```

用“重复错误是否减少、独立方向是否更有依据、选稿修改是否稳定”判断经验是否开始生效。新文档数量和生成次数不作为设计质量指标。
